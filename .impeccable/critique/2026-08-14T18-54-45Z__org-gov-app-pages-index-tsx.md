## Design Specificity Verdict

**Authored, decisively. This is the top decile of what I see.**

The composition could not be lifted onto another product without breaking. The
milestone track is a dimension line with drafting anatomy intact — witness ticks
generated by the data so a run of 3 and a run of 12 both draw correctly, a taller
terminator closing the far end, the measurement set as a callout beneath. The hero
drawing is a chain whose surface is the project's own ID in binary, deliberately
unlit, with depth from fog rather than lighting. The navigation refuses the
hamburger and scrolls instead. `--grid-ink` measures 1.08:1 against the paper —
substrate, not decoration.

What separates this from "themed" work is that the metaphor is load-bearing on
decisions nobody would notice: shadows tinted with the paper hue rather than black
alpha, because black alpha would turn the warm ground grey. Mono used semantically
to mark recorded values rather than as a costume for "technical". A single light
theme argued for rather than defaulted to.

**Deterministic scan**: `detect.mjs` over `org-gov-app/pages` and
`org-gov-app/components` returned `[]` — zero findings, exit 0. Supporting static
checks confirm it: **zero** colour literals outside the token layer, **zero**
border-radius values outside the permitted `0` / `2px` / `9999px` set, `tsc
--noEmit` clean, **zero** icon-only controls without an accessible name, **zero**
images without `alt`, **zero** `target="_blank"` without `rel="noopener"`, **zero**
`will-change` uses. 15 interactive elements pin their minimum target to
`--space-11` (2.75rem). `prefers-reduced-motion` is honoured in three places, and
collapses the duration scale rather than killing transitions, so state changes
still apply instantly instead of getting stuck.

**False positive:** a naive scan flags 3 `aria-hidden="true"` regions on `/` as
containing focusable children. They are the `→` arrow spans *inside* link
elements, plus the WebGL stage div. `aria-hidden` on a decorative child of a link
is correct usage. Not a finding.

**Visual overlays**: not available. No browser automation exists in this session
(no Playwright, Puppeteer, or browser MCP), so no script injection and no
user-visible overlay was attempted. The fallback signal is rendered-HTML analysis
against the dev server on :3001 across all five routes.

## Overall Impression

The visual system is better than the information architecture serving it. The
craft floor is essentially met — this is a genuinely authored world with real
discipline behind it, and the token layer is the most rigorous part of the
codebase. What lets it down is that the record does not fully exist when the
conditions are imperfect: without JavaScript the central sheet shows a loading
message that will never resolve, and every page in the site ships an empty
`<title>`.

The single biggest opportunity: the site's stated purpose is to be **cited and
returned to**. Right now it cannot be bookmarked meaningfully, cannot be told
apart in a tab strip, cannot be linked with a preview title, and cannot be read at
all without JS on its most important sheet. Those are not polish items on a
governance record — they are the record failing to be a record.

## What's Working

**1. The zeros are the design.** Most teams in this position would show a roadmap,
a burn-up chart, or "₳230,000 in flight". This shows `₳0` distributed and `0/10`
delivered on the front sheet with a spec note reading "Nothing drawn down before a
vote". The revision-red stamp is spent on the one genuinely outstanding fact and
nothing else. That is a real position, held under pressure, and it is the most
persuasive thing on the site precisely because it is not trying to persuade.

**2. Provenance is structural, not decorative.** The record table is three columns
— key, figure, and where the figure came from — so a number cannot appear without
a source. The proposals page refuses to stamp a fetch date when nothing was
actually fetched, with a comment explaining that an empty payload stamped with
today's date would read as "checked today, all current". That is a subtle,
correct, load-bearing honesty decision.

**3. Degradation is designed, not bolted on.** The hero drawing ships an SVG
fallback that draws the same object from the same shared geometry constants rather
than a similar-looking approximation, probes for a WebGL context before importing
three.js, stops rendering off-screen and on tab-hide, and handles context loss.
This is the exception that makes the `/catalyst-proposals` no-JS failure below so
conspicuous.

## Priority Issues

### [P1] The record does not exist without JavaScript, on the sheet that matters most

**What**: `/catalyst-proposals` initialises `isLoading = true` and early-returns a
header plus `Reading the record…`. With JS disabled the `useEffect` never runs, so
that state is permanent. Meanwhile `FUND_15_PROPOSALS` — the filed figures, the
actual subject of the page — sits in local data and never renders. The code even
carries a comment saying the page should degrade to local filings; that path only
executes after a fetch *completes and fails*, never when the fetch never starts.

**Why it matters**: This breaks a binding product constraint ("readable without
JavaScript or WebGL... degrade to complete, never to empty"). It also produces the
worst class of status message — one asserting that work is in progress which will
never finish. A funder auditing delivery on a locked-down browser sees a site that
appears broken, on the page holding the numbers they came for.

**Fix**: Seed state from `FUND_15_PROPOSALS` instead of `null`/`true` and render
the register immediately, letting the fetch augment it with funded proposals. The
loading indicator becomes a secondary "checking for funded proposals" note rather
than a gate in front of the content. Same treatment for `/projects` and
`/org-stats`, which have no local data to fall back on and should carry a
`<noscript>` block naming the source and linking to github.com/BlockPrintio.

### [P1] Every page ships an empty `<title>`

**What**: `_app.tsx:32` is `<title>{config.mainOrganization.displayName} Governance
Dashboard</title>`, which hands React a two-element array. React refuses to render
array children in `<title>` and drops it. Confirmed empty on all five routes. Two
other `<title>` tags in the codebase already use the template-string form that
avoids this.

**Why it matters**: For a record whose purpose is to be cited, bookmarked and
returned to across months, this hits every one of those. Browser tabs are
unlabelled, bookmarks are unnamed, search results and shared links have no title,
and screen readers announce nothing on page load. The og:title tags are correct, so
the failure is invisible in social previews and shows up exactly where the repeat
auditor lives.

**Fix**: `<title>{`${config.mainOrganization.displayName} Governance Dashboard`}</title>`,
and give each sheet its own title so the five routes are distinguishable.

### [P2] Two sections on the overview render `class="undefined"`

**What**: `pages/index.tsx:167` and `:205` reference `styles.record` and
`styles.index`, neither of which is defined in `page.module.css`. The rendered
output is `class="undefined sheet-section"` on both.

**Why it matters**: No visual damage today — `sheet-section` carries the rhythm —
but it is a live trap. `undefined` is a valid CSS class name, so any stylesheet
that ever defines `.undefined` silently restyles both sections, and the dead
reference reads as intent to a future maintainer.

**Fix**: Drop the two `styles.X` references, or define the classes if they were
meant to carry something.

### [P2] Nothing here serves the repeat auditor

**What**: The product record names "funders and reviewers auditing delivery,
returning repeatedly over months" as a primary audience. The site gives them no
affordance: no permalink to a filtered view of the register, no machine-readable
export (the `/api/*` routes exist but are never surfaced), no "as of" comparison
against a previous reading, no changelog of what moved since last visit.

**Why it matters**: This audience's whole job is diffing today against last month.
They currently have to do that by memory or by screenshot. The data to support it
already exists — timestamps are already read and displayed.

**Fix**: Surface the JSON endpoints as a "machine-readable record" link in the
footer or title block; make filter state URL-encoded so a filtered register can be
linked; consider a "last changed" stamp per row rather than per page.

### [P2] A newcomer has no way in

**What**: No glossary and no orientation. "Catalyst", "Fund 15", "milestone
sign-off", "DRep", "₳", and "as filed" all appear unexplained. The nav's
"Governance record" subtitle is the only orientation text on the site.

**Why it matters**: "The Cardano community at large" is a confirmed audience, and
the front sheet is written for someone who already knows what Project Catalyst is.
A developer arriving from a GitHub link bounces off the vocabulary before reaching
the argument the zeros are making.

**Fix**: One short "How to read this sheet" block on the overview, or inline
`<abbr>`/definition treatment on first use of each term. It fits the drafting world
natively — a real drawing carries a legend.

## Persona Red Flags

**Sam (accessibility-dependent, screen reader + keyboard)**: Lands on a page whose
title announces as nothing — the first thing a screen reader reads is absent on
every route. Focus indicators are strong (one treatment site-wide, never animated,
with a correctly reasoned inset variant for fields inside a framed strip) and no
control is icon-only, so navigation itself is solid. But the loading→loaded
transition on `/catalyst-proposals`, `/projects` and `/org-stats` has `role="status"`
on the loading paragraph only; when content replaces it, nothing announces that the
record arrived. Sam hears "Reading the record…" and then silence.

**Riley (stress tester)**: Disables JavaScript and finds `/catalyst-proposals`
permanently loading with the data sitting in the bundle. Kills the network and gets
a genuinely good "Incomplete" notice on the proposals page naming exactly what is
missing — the best error copy on the site. Then hits `/org-stats` with a failing
API and gets a raw `err.message` such as "Failed to fetch" surfaced directly into
the UI, which is a technical string, not an explanation.

**Jordan (first-timer)**: Reads "Sheet 01 of 05" and has no model for what a sheet
is or why they are numbered. Reaches "0 of 10 milestones delivered" with no idea
whether that is normal, alarming, or expected before a vote — the answer is "wholly
expected", the page knows it, and the spec note says so, but the title block's
"Awaiting vote" is the only thing carrying that reassurance and it is set in the
quietest type on the page.

## Minor Observations

- `org-stats.tsx:24` and `projects.tsx:50` surface `err.message` directly. Plain
  language should replace the technical string; keep the detail in `console.error`.
- Eyebrow format diverges: the overview says "Public record" while every other
  sheet says "Sheet NN · Section". The overview's sheet number now lives in the
  title block, so the divergence is defensible, but it means the sheet-numbering
  system is taught in two different places.
- `next lint` is non-functional — it throws "Converting circular structure to JSON".
  `package.json` pins `eslint-config-next@^16.1.3` against `next@15.3.8`; the major
  mismatch is the likely cause. The project currently has no working lint gate.
- `/api/packages` returns 500 on a connect timeout to `gov.meshjs.dev`. Unverified
  from this sandbox (no outbound network), so it may be environmental.
- `figurePlaceholder` and the chain's `.stage` now share `3/2` and `4/5` ratios
  across the same breakpoint, so no layout shift on load. Worth keeping in sync
  deliberately — they are declared in two different files.

## Questions to Consider

- The zeros are the most credible thing on this site. What would it look like to
  make that the *explicit* argument rather than an implication a careful reader
  assembles — a single line that says "we have asked for ₳230,000 and drawn down
  nothing, because nothing has been voted yet"?
- The record's most valuable future state is a *diff*: what moved since last time.
  What would the front sheet look like if it were designed for the second visit
  rather than the first?
- The drafting world has a legend, a scale, and a revision history block — all
  standard sheet furniture the site has not used yet. Which of those is the site
  actually missing as *information*, not as decoration?
- If a funded proposal lands tomorrow and the delivery column starts filling, does
  the front sheet still work? The open-item stamp is sized for exactly one
  outstanding thing.
